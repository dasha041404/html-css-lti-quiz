# Тренажёр по HTML и CSS: Moodle + LTI 1.3

Внешний инструмент для Moodle. Студент открывает элемент курса, отвечает на три вопроса по HTML/CSS и нажимает «Проверить и отправить в Moodle». Оценка (0–10) появляется в журнале курса.

- Node.js 20+, Express, `jose` (проверка и подпись JWT), MongoDB Atlas.
- LTI 1.3 написан без готовой LTI-библиотеки: вход через OIDC, проверка `id_token`, отправка оценки через AGS (Assignment and Grade Services).
- Вопросы и правильные ответы: `src/quiz.mjs`. Веса 3/3/4, максимум 10.

## Структура

```
src/server.mjs   маршруты, сессии, API
src/lti.mjs      LTI 1.3: login, проверка запуска, токен и отправка оценки
src/quiz.mjs     вопросы и проверка ответов
src/db.mjs       подключение к MongoDB и индексы
public/          интерфейс (app.html, assets/app.css, assets/app.js)
test/            тесты (npm test)
render.yaml      описание сервиса для Render
```

Что хранится в MongoDB: ключ инструмента (чтобы он не менялся при перезапуске Render), одноразовые `state`, сессии (45 минут), попытки студентов.

## Порядок работ

Нужен именно такой порядок: Moodle выдаёт Client ID только после того, как вы зарегистрировали в нём адреса вашего приложения, а адреса даёт Render.

### 1. MongoDB Atlas

1. На https://www.mongodb.com/cloud/atlas создайте аккаунт и бесплатный кластер M0.
2. Database Access: добавьте пользователя с паролем (пароль без спецсимволов проще).
3. Network Access: добавьте `0.0.0.0/0` (у бесплатного Render нет постоянного IP).
4. Connect → Drivers: скопируйте строку `mongodb+srv://...`, подставьте пароль и добавьте имя базы перед `?`: `...mongodb.net/lti_quiz?retryWrites=true&w=majority`.

### 2. GitHub

1. Распакуйте zip.
2. Создайте на GitHub пустой публичный репозиторий.
3. «Add file → Upload files», перетащите всё содержимое папки проекта (не сам zip), нажмите Commit. Либо через git: `git init && git add . && git commit -m "init" && git remote add origin <url> && git push -u origin main`.
4. Файл `.env` и папка `node_modules` в репозиторий не попадают (они в `.gitignore`). Никогда не публикуйте строку MongoDB и пароли.

### 3. Render (первый деплой)

1. https://render.com → New → Web Service → выберите репозиторий (либо New → Blueprint, он прочитает `render.yaml`).
2. Runtime: Node. Build Command: `npm install --omit=dev`. Start Command: `npm start`. Health Check Path: `/healthz`. План Free.
3. Environment Variables: `NODE_VERSION=22`, `MONGODB_URI=<строка из Atlas>`, `MOODLE_ISSUER=https://dasaveleva.gnomio.com` (адрес вашего Moodle без слэша). `MOODLE_CLIENT_ID` и `MOODLE_DEPLOYMENT_ID` пока оставьте пустыми.
4. Дождитесь статуса Live. Откройте `https://<имя>.onrender.com/`: страница покажет четыре адреса для Moodle и статус «нужно задать MOODLE_ISSUER, MOODLE_CLIENT_ID…». Это нормально.

Бесплатный сервис Render засыпает через 15 минут и просыпается около минуты. Откройте `/healthz` перед проверкой.

### 4. gnomio (Moodle), регистрация инструмента

Нужен вход администратором.

1. Администрирование сайта → Плагины → Модули занятий → Внешний инструмент → Управление инструментами → «Настроить инструмент вручную».
2. Заполните:
   - Название: `Тренажёр HTML/CSS`
   - URL инструмента: `https://<имя>.onrender.com/lti/launch`
   - Версия LTI: **LTI 1.3**
   - Тип публичного ключа: **Набор ключей (Keyset URL)**
   - Публичный набор ключей: `https://<имя>.onrender.com/lti/keys`
   - URL инициации входа: `https://<имя>.onrender.com/lti/login`
   - URI перенаправления: `https://<имя>.onrender.com/lti/launch`
   - Использование настроек инструмента: «Показывать как преднастроенный инструмент при добавлении внешнего инструмента»
   - Контейнер запуска по умолчанию: **Новое окно**
3. Услуги: «IMS LTI Assignment and Grade Services» → «Использовать эту услугу для синхронизации оценок и управления столбцами».
4. Конфиденциальность: «Принимать оценки от инструмента» → **Всегда**. Имя и email можно не передавать.
5. Сохраните. В списке инструментов нажмите значок «Просмотр деталей конфигурации» и скопируйте:
   - **Platform ID** → `MOODLE_ISSUER` (должен совпасть с адресом Moodle, без слэша на конце)
   - **Client ID** → `MOODLE_CLIENT_ID`
   - **Deployment ID** → `MOODLE_DEPLOYMENT_ID`
   (Authentication request URL, Access token URL и Public keyset URL подставляются автоматически от `MOODLE_ISSUER`. Если в деталях они другие, задайте `MOODLE_AUTH_URL`, `MOODLE_TOKEN_URL`, `MOODLE_JWKS_URL`.)

### 5. Render: вторая настройка

В Environment сервиса впишите `MOODLE_CLIENT_ID`, `MOODLE_DEPLOYMENT_ID` (и проверьте `MOODLE_ISSUER`), сохраните. Render перезапустит сервис. На главной странице статус станет «готово».

### 6. Элемент в курсе

1. Откройте курс → Режим редактирования → «Добавить элемент или ресурс» → Внешний инструмент.
2. Преднастроенный инструмент: «Тренажёр HTML/CSS». Контейнер запуска: «Новое окно».
3. Раздел «Оценка»: максимальная оценка 10 (если оставить 100, Moodle пересчитает пропорционально).
4. Сохраните и вернитесь на курс.

### 7. Проверка

1. Создайте пользователя «Тестовый студент» и запишите его на курс ролью «Студент». Войдите под ним в другом браузере или в режиме инкогнито (либо используйте «Сменить роль на… → Студент»).
2. Откройте элемент. Откроется новое окно с тремя вопросами.
3. Ответьте и нажмите «Проверить и отправить в Moodle». Должно появиться «Оценка отправлена в журнал Moodle».
4. Под преподавателем: Курс → Оценки → Просмотр журнала. Там будет оценка студента.

Правильные ответы для самопроверки: `href`, `:hover` (или `hover`), `flex`.

## Если не работает

| Симптом | Причина |
|---|---|
| `/app` отвечает 401 | Открыт напрямую, а не из Moodle. Так и должно быть. |
| «Неизвестная платформа: iss не совпадает» | `MOODLE_ISSUER` не равен Platform ID. Проверьте схему, слэш на конце. |
| «client_id / deployment_id не совпадает» | Неверно скопированы значения из деталей конфигурации. |
| «Неизвестный или уже использованный state» | Страницу обновили или вернулись назад. Откройте элемент из курса заново. |
| «Подпись id_token не прошла проверку» | Неверный `MOODLE_JWKS_URL` или часы сервера. |
| Нет строки в журнале, кнопка отключена | Не включена услуга AGS или «Принимать оценки» (шаги 3–4 в разделе 4). После изменения откройте элемент заново. |
| «Moodle не выдал токен (400/401)» | В Moodle указан не тот Keyset URL (`/lti/keys`), либо сервис Render спал. Повторите отправку. |
| Первый вход очень медленный | Render разбудил сервис. Подождите около минуты. |

Логи: Render → ваш сервис → Logs.

## Локальный запуск

```
npm install
npm test
export MONGODB_URI="mongodb+srv://..."
npm start
```
Без регистрации в Moodle приложение стартует в режиме подготовки: открыта главная страница и `/lti/keys`.

## Как устроена проверка запуска

1. Moodle вызывает `/lti/login`. Приложение сверяет `iss`, `client_id`, `deployment_id`, сохраняет одноразовые `state` и `nonce` в MongoDB и перенаправляет на авторизацию Moodle.
2. Moodle отправляет `id_token` на `/lti/launch`. Приложение проверяет подпись по ключам Moodle, `iss`, `aud`, срок, `nonce`, `deployment_id`, тип сообщения и роль. Затем создаёт сессию (cookie `sid`, HttpOnly).
3. Браузер отправляет только ответы и `requestId`. Пользователь, курс и адрес строки журнала берутся из проверенного запуска. Для POST нужны CSRF-токен и свой Origin.
4. Оценка уходит в Moodle: токен по `client_credentials` с подписанным JWT, затем `POST <lineitem>/scores`. Повторная отправка той же формы с тем же `requestId` не создаёт новую попытку. Пока последний результат не доставлен, новую попытку начать нельзя.
